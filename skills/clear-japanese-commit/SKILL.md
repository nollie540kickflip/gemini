# わかりやすい日本語のコミットメッセージの作成

ユーザーから変更のコミットやコミットメッセージの作成を依頼された場合、以下のガイドラインに従って、第三者が見ても理解しやすい、高品質でプロフェッショナルな日本語のメッセージを作成してください。

## コミットメッセージのガイドライン

1. **フォーマット (Conventional Commits)**:
   - 1行目（タイトル）は Conventional Commits のフォーマットを使用します。
   - `type(scope): subject`
   - よく使われる type: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `chore`
   - `subject` は簡潔な日本語の要約にしてください。

2. **本文 (詳細)**:
   - 変更が自明で軽微なもの以外は、必ず本文を含めてください。
   - 変更の詳細は箇条書き（`- `）を用いて列挙します。
   - 単なるコードの差分の直訳ではなく、「何を」そして「なぜ」変更したのかに焦点を当ててください。

3. **言葉遣いとトーン**:
   - プロフェッショナルな日本語を使用してください（コミットメッセージ内では「です・ます調」である必要はありません。「〜を追加」「〜を修正」といった標準的なコミットの表現を使用してください）。
   - PRのレビュアーや、後から履歴を見る第三者がその変更の影響を理解できるように心がけてください。

## 例文

```text
feat(auth): ユーザー認証にOAuth2.0を追加

- Googleログイン用のAPIエンドポイントと関連するルーティングを追加
- 既存のセッション管理処理を拡張し、外部プロバイダのトークンを安全に保持できるように変更
- 必須の環境変数として OAUTH_CLIENT_ID および OAUTH_CLIENT_SECRET のチェック処理を導入
```

## 実行手順

1. `git status` と `git diff` を実行して、どのような変更が行われたかを把握します。
2. **コミットメッセージを作成する前に、今回の変更がプロジェクトのドキュメント（`README.md` などの環境変数、セットアップ手順、仕様など）に影響を与えるか確認します。** 影響がある場合は、まず該当するドキュメントを最新の状態に更新し、それも一緒にステージングしてください。
3. `git add <file>` を使用して必要なファイルをステージングします。
4. 上記のガイドラインに従ってコミットメッセージを作成します。
5. `run_command` ツールを使用してコミットを実行します。
   - **ヒント**: コマンドラインから `git commit` を実行する場合、複数の `-m` フラグを使用してタイトルと本文の段落をきれいに分けるか、一時ファイルにメッセージを書き込んで `git commit -F <file>` を使用してください。
6. 生成したコミットメッセージと共に、実行が成功したこと（ドキュメントを更新した場合はその旨も）をユーザーに報告します。
