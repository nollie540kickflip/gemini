# プロジェクト内部レビューの実行

ユーザーからプロジェクト全体のレビューを依頼された場合、以下の手順と観点でコードベースを調査し、詳細なレビューレポート（Artifact）を生成してください。

## レビューの3つの観点

1. **アーキテクチャと保守性（疎結合）**:
   - 各コンポーネントやモジュールが密結合になっていないか。
   - データベース処理、外部API通信、ビジネスロジック、UI/プレゼンテーション層などが適切に分離されているか。
   - 今後の機能拡張や単体テスト・結合テストが容易な構造になっているか。

2. **ライブラリの依存関係とサポート状況**:
   - プロジェクトのパッケージ管理ファイル（例: `package.json`, `pyproject.toml`, `go.mod`, `build.gradle`, `pom.xml` など）を確認し、使用されている主要なライブラリを特定する。
   - 開発が停止している、またはサポートが終了・非推奨となっているライブラリが含まれていないかを調査し、必要に応じて代替ライブラリを提案する（不明な場合は `search_web` ツールなどで最新状況を確認する）。

3. **ベストプラクティスの踏襲**:
   - 使用している言語やフレームワーク固有の標準的なコーディング規約に従っているか。
   - 環境変数やシークレットの安全な管理、適切なエラーハンドリングと例外処理が行われているか。
   - 言語に応じた型システムの活用（静的型付け、型アノテーションなど）や、保守・運用に役立つ適切なログ出力が行われているか。

## 実行手順

1. **ファイル構成の把握**:
   - `list_dir` ツールや `run_command` などを活用して、プロジェクト内の主要なソースコードのディレクトリ構造を把握します。
2. **依存関係ファイルの分析**:
   - プロジェクトルートにあるパッケージ管理ファイルを読み込み、依存関係の状況を分析します。
3. **コードの静的レビュー**:
   - 主要なソースファイル（例: `src/`, `app/`, `lib/`, `components/` などのディレクトリ配下）を `view_file` で順番に確認し、上記の観点に基づいてレビューを行います。
4. **レビューレポートの作成**:
   - Artifact機能を使用して `internal_review_report.md` のようなファイル名でレポートを作成し、発見した課題、改善案（具体的なコードスニペットを含む）、評価できるポイントを整理します。
5. **ユーザーへの報告**:
   - レポートの作成が完了したことをユーザーに伝え、内容の確認や特定の課題に対する深掘りが必要かどうかを尋ねます。
